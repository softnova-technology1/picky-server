1. Customer WhatsApp OTP Authentication & JWT Session

Passwordless login using official WATI WhatsApp REST API, Redis 5-minute TTL, and HTTP-only JWT cookies.

WATI API • Zero Twilio
01
↓
👤 Customer Inputs 10-Digit Mobile Number
Customer → picky_client

User enters their phone number (e.g. 9876543210) on the Login/Register modal. Client performs regex validation.

POST /api/v1/auth/send-otp →
02
↓
⚡ Server Generates 6-Digit Secure OTP & Stores in Redis
picky-server → Redis Cache

Express server crypto-generates a 6-digit random code and saves it to Redis key otp:919876543210 with a 300-second (5-minute) TTL.

await redis.set(`otp:91${phone}`, otp, 'EX', 300);
POST https://wati-server/api/v1/sendSessionMessage →
03
↓
📲 WATI Dispatches WhatsApp Message to Customer
WATI API → Customer WhatsApp

WATI sends an instant WhatsApp message to the customer: "Your Picky OTP is: 849201. Valid for 5 minutes. Do not share with anyone."

POST /api/v1/auth/verify-otp →
04
✔
🎉 Server Verifies OTP, Upserts User in MongoDB & Signs JWT
picky-server → MongoDB → picky_client

If code matches Redis store: User is created or updated in MongoDB Atlas. Server sets accessToken in response and refreshToken in HttpOnly cookie.

{ "success": true, "user": { "_id": "66d8...", "phone": "+919876543210", "role": "customer" }, "accessToken": "eyJhbGci..." }
✔ Zero Twilio Dependency: System uses official WATI REST API exclusively. When local test keys are present, the terminal cleanly outputs the OTP box for fast offline testing.

2. Guest to Authenticated Cart & Wishlist Sync

Seamless browser LocalStorage persistence that automatically merges into MongoDB Atlas upon login.

Zustand • LocalStorage Sync
01
↓
🛒 Guest User Browses & Adds Items to Cart
picky_client (LocalStorage)

Unauthenticated user adds products to cart or wishlist. Zustand store saves the list directly to browser localStorage.getItem('picky_guest_cart').

User Logins via WhatsApp OTP →
02
↓
⚡ Frontend Dispatches Auto-Merge Payload
picky_client → POST /api/v1/cart/merge

Immediately upon receiving the JWT token, frontend extracts guest cart items and dispatches an atomic merge request to the backend.

MongoDB Document Update →
03
✔
🍃 MongoDB Merges Quantities & Clears LocalStorage
MongoDB Atlas → picky_client

MongoDB combines existing cart items with the guest items, preventing duplication. LocalStorage is wiped and the user sees their full synced cart.

3. 100% Razorpay Prepaid Checkout & Atomic Stock Deduction

Zero COD. All orders are 100% prepaid online with dynamic backend price verification and HMAC-SHA256 signature validation.

100% Online • Zero COD
01
↓
🛒 Customer Clicks "Proceed to Pay" at Checkout
picky_client → POST /api/v1/orders/razorpay/create-order

Client passes item IDs, quantities, address, and coupon code. No price from the client is trusted.

Dynamic DB Price & Stock Check →
02
↓
⚡ Server Calculates True Price & Creates Razorpay Order
picky-server → Razorpay API

Server queries MongoDB Product.findById for active stock and real price, applies valid coupon, and calls Razorpay API to generate order_id.

const rzpOrder = await razorpay.orders.create({ amount: calculatedTotal * 100, // in paise currency: 'INR', receipt: `rcpt_${Date.now()}` });
Razorpay Standard Popup Modal →
03
↓
💳 Customer Pays via UPI / GPay / PhonePe / Card / NetBanking
Customer → Razorpay Modal

Customer completes payment in Razorpay modal. Razorpay returns razorpay_payment_id, razorpay_order_id, and razorpay_signature.

POST /api/v1/orders/razorpay/verify →
04
✔
🔐 HMAC-SHA256 Signature Verification & Atomic Stock Deduction
picky-server → MongoDB → WATI Alert

Backend verifies the crypto signature. Upon match:

  1. Atomic stock deduction via Product.findByIdAndUpdate(..., { $inc: { stock: -qty } })
  2. Order saved in MongoDB Atlas with status 'confirmed' and paymentStatus: 'paid'.
  3. WATI WhatsApp Order Confirmation notification dispatched instantly to customer's phone!

Zero COD Guarantee: Because all orders require successful Razorpay cryptographic verification, the store eliminates fake COD orders, RTO losses, and unpaid deliveries completely.

4. Admin-Driven 4-Stage Order Tracking & AWB Dispatch

Store-controlled order status progression with automated WATI WhatsApp alerts and zero third-party courier API dependencies.

4-Stage Progress • WATI Alerts
01
↓
💳 Stage 1: Order Confirmed & Paid
System Trigger

Automatically set upon successful Razorpay payment verification. WATI sends confirmation message.

02
↓
📦 Stage 2: Admin Enters AWB & Marks "Dispatched & Shipped"
Admin Portal → PATCH /api/v1/admin/orders/:id/status

Admin packs the order, books courier (e.g. BlueDart / Delhivery), and inputs the AWB tracking number in /pickyadmin-softnova2026/orders/:id.

// WATI Dispatches WhatsApp Alert: "Order #PKY-89421 shipped! Courier: BlueDart. AWB: BD-8492049102. Track live on Picky."
03
↓
🚚 Stage 3: Admin Updates Status to "Out for Delivery"
Admin Portal → MongoDB

Customer's live order page updates in real-time via TanStack Query polling.

04
✔
🎉 Stage 4: Delivered & Completed
Admin → WATI Alert → Customer

Admin marks delivered. Final WATI WhatsApp celebration message sent: "Your Picky order #PKY-89421 has been delivered! Thank you for shopping with Picky! 🎉"

5. Strict Admin-Only Order Cancellation & Stock Restoration

Customers cannot cancel confirmed prepaid orders. Only the Admin can cancel orders, which automatically restores inventory stock in MongoDB Atlas.

Admin-Only • Atomic Stock Restore
01
↓
👤 Customer Sees "Contact Support" on Confirmed Order
picky_client UI Protection

The client interface has no self-cancellation button for confirmed orders. The customer contacts store support via WhatsApp or email.

02
↓
👑 Admin Opens Order in Admin Portal & Clicks "Cancel Order"
/pickyadmin-softnova2026 → PATCH /api/v1/admin/orders/:id/status

Admin reviews the request and clicks Cancel in the admin order management panel.

03
✔
🍃 Backend Sets Status `cancelled` & Restores MongoDB Inventory Stock
picky-server → MongoDB Atomic `$inc`

Backend iterates over all items in the order and executes an atomic MongoDB increment to restore product stock quantity back to inventory.

for (const item of order.items) { await Product.findByIdAndUpdate(item.product, { $inc: { stock: item.quantity } // Inventory stock restored }); }
Refund Handling: Once cancelled by Admin, the Razorpay payment ID is marked for refund processing directly through the Razorpay Dashboard or automated refund API.
