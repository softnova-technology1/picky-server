1. Current Project Status

Deep architectural inspection of existing implementations versus missing dependencies.

✅ Completed Architecture Working

Clean, enterprise-grade layered backend with comprehensive security middleware.

  • Middleware: Helmet, CORS, MongoSanitize, XSS-Clean, Tiered Rate Limiters (API, Auth, OTP).
  • Mongoose Models: User, Product, Category, Order, Cart, Wishlist, Coupon, CouponUsage, Discount, Inventory.
  • Core Services: Atomic session transaction in order.service.js, crypto OTP generation in auth.service.js.
  • Frontend Layouts: 15+ Customer views & 11 Admin Dashboard modules built in React 18 + Tailwind.

⚠️ Partially Completed Partial

Features implemented with fallback mechanisms that require live configuration.

  • Redis: In-memory Map fallback active on localhost. Wipes OTPs & refresh tokens on restart.
  • Razorpay: Mock bypass active for placeholder keys. Needs real test keys and frontend script tag.
  • Storage & Notifications: Cloudinary / S3 use Unsplash image fallbacks; WATI uses console logging.
  • Frontend Services: 5 client services mask server errors with silent mock fallbacks.

❌ Still Missing Missing

Missing endpoints and database records preventing full live execution.

  • Admin & Catalog Seeds: Zero admin accounts and zero products/categories in MongoDB Atlas.
  • Missing Routes: /api/v1/customers, /api/v1/settings, /api/v1/inventory.
  • Cart Merge: Automatic guest-to-server cart merge post-OTP login trigger missing.
  • Webhook Secret: RAZORPAY_WEBHOOK_SECRET omitted from .env.

2. All Required Corrections

Categorized defect matrix detailing exact file paths and remedies.

2.1 Critical Security Corrections Critical

  • Rotate JWT Secrets: Replace literal placeholder strings in picky-server/.env with two distinct 256-bit crypto strings.
  • Fix CORS Origin: Add http://localhost:5173 to ALLOWED_ORIGINS in picky-server/.env to prevent Vite blocking.
  • Eradicate Admin Demo Bypass: Delete handleDemoBypass() and remove hardcoded credentials in AdminProtectedRoute.jsx.
  • Enforce Webhook Signature: Require RAZORPAY_WEBHOOK_SECRET in env.js and verify on webhook entry.

2.2 Backend & API Corrections High

  • MongoDB Connection: Remove redundant dbName: 'picky' and raise serverSelectionTimeoutMS: 30000 in db.js.
  • Create Customer API: Build /api/v1/customers route and controller for Admin customer reporting.
  • Create Store Settings API: Build /api/v1/settings for store theme, banners, and announcement texts.
  • Create Inventory API: Build GET /api/v1/inventory and PATCH /api/v1/inventory/:productId for variant stock management.

2.3 Database & Model Corrections Medium

  • Subcategory Indexing: Index { parentCategory: 1, isActive: 1 } in category.model.js.
  • Order Tracking Fields: Ensure courierName, trackingNumber, trackingUrl, and shippedAt exist on order.model.js.
  • Cart TTL Index: Add 30-day expiration TTL on updatedAt for guest carts in cart.model.js.

2.4 Frontend & UI/UX Corrections High

  • Strip Silent Mock Fallbacks: Remove catch blocks in product, category, cart, and order services that mask backend drops.
  • Embed Razorpay Checkout: Add <script src="https://checkout.razorpay.com/v1/checkout.js"></script> to index.html.
  • Live Stock Indicators: Read inventory directly from product variant models rather than mockStockStore.js.

3. Implementation Plan (Phases 0 → 6)

Chronological step-by-step roadmap ordered by strict technical dependency.
Phase 0: Immediate Security & Configuration Unblocking
Blocker • Immediate
Objective: Fix vulnerable JWT secrets, open CORS for Vite on port 5173, and eliminate the dangerous demo bypass in the admin login form.
1 Generate Cryptographic JWT Secrets
Execute in terminal to create two 64-character hex strings: 
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
Update picky-server/.env with real values for JWT_ACCESS_SECRET and JWT_REFRESH_SECRET.
2 Fix CORS Allowed Origins
In picky-server/.env, update line 32: 
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:5173
3 Optimize MongoDB Connection Options
In picky-server/src/config/db.js, remove dbName: 'picky' from options and set serverSelectionTimeoutMS: 30000.
4 Eradicate Admin Login Demo Bypass
In AdminProtectedRoute.jsx, delete handleDemoBypass(), clear hardcoded credentials from useState(''), and render an error notification on failed login.
Phase 1: Database Initialization & Seeding
High Priority
Objective: Populate MongoDB Atlas with foundational records so all real API queries return data.
1 Create Admin User Script (createAdmin.js)
Build script in picky-server/scripts/createAdmin.js. Hash password with bcrypt (12 rounds) and upsert user with role: 'admin' and email: 'admin@picky.com'. Run: 
node scripts/createAdmin.js
2 Seed Categories & Subcategories (seedCategories.js)
Create parent categories (Men, Women, Accessories, Shoes) and children (Shirts, T-Shirts, Dresses, Sneakers) with characteristic schemas.
3 Seed Product Catalog (seedProducts.js)
Insert 15–20 fashion products linking to valid category ObjectIds, complete with images, variant sizes, colors, SKU, and stock quantities.
4 Verify Database Records
Execute query to confirm document counts in MongoDB Atlas: users, categories, products, and inventory items.
Phase 2: Missing Backend Endpoints Implementation
High Priority
Objective: Close all API gaps required by Admin views and client branding settings.
1 Build Customers Management API (/api/v1/customers)
Create customer controller, routes, and attach to app.js. Provide paginated list of customers with total orders and total spend.
2 Build Store Settings API (/api/v1/settings)
Create settings.model.js, settings.controller.js, and settings.routes.js. Expose GET (public) and PATCH (admin).
3 Build Inventory Stock Management API (/api/v1/inventory)
Expose GET /api/v1/inventory (variant stock matrix) and PATCH /api/v1/inventory/:productId (adjust stock with audit log).
Phase 3: Frontend Service Decoupling & Real API Wiring
Medium Priority
Objective: Eliminate mock fallbacks so client views render true live data from MongoDB Atlas.
1 Clean Category Service (category.service.js)
Remove categoryMockData.js fallback. Return API data directly and let errors bubble to UI error handlers.
2 Clean Product Service (product.service.js)
Remove data.js mock imports. Wire query parameters (category, subcategory, price, sort) directly to backend endpoint.
3 Clean Cart & Coupon Service (cart.service.js)
Remove local validateCoupon(). All coupon verifications must execute via POST /api/v1/cart/coupon.
4 Clean Order Service (order.service.js)
Remove ordersMockData.js. Fetch genuine order history and order tracking details from backend.
Phase 4: Admin Panel Complete Real-Data Integration
Medium Priority
Objective: Connect all Admin management views to real backend endpoints and retire fake stores.
1 Wire Admin Coupons (AdminCoupons.jsx)
Replace useCouponStore with direct API calls via admin.service.js. Create, toggle, and delete real coupons.
2 Wire Admin Inventory (AdminInventory.jsx)
Deprecate mockStockStore. Load live SKU stock from /api/v1/inventory and submit stock adjustments to backend.
3 Wire Admin Customers (AdminCustomers.jsx)
Connect customer table to GET /api/v1/customers. Display registered customers, spend metrics, and joined dates.
4 Wire Settings & Customization (AdminSettings.jsx)
Connect branding, banners, and announcement texts to /api/v1/settings.
Phase 5: Payment Gateway & Order Lifecycle Verification
High Priority
Objective: Complete full transaction cycle from Razorpay checkout to inventory deduction and manual courier fulfillment.
1 Embed Razorpay Checkout SDK
Add <script src="https://checkout.razorpay.com/v1/checkout.js"></script> to picky_client/index.html.
2 Configure Real Test Keys & Webhook Secret
Add active RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, and RAZORPAY_WEBHOOK_SECRET to picky-server/.env.
3 Test End-to-End Checkout Flow
Add item → Apply coupon → Checkout → Razorpay popup → HMAC Signature verification → MongoDB transaction → Order success screen.
4 Test Courier Tracking Assignment
In AdminOrders.jsx, update status to shipped, assign courier (e.g. Delhivery) and tracking number. Verify customer tracking page reflects updates.
Phase 6: Production Infrastructure & Real Services
Pre-Launch
Objective: Deploy managed cloud infrastructure for persistent sessions, image hosting, and SMS/WhatsApp notifications.
1 Setup Managed Redis (Upstash / Cloud)
Supply rediss:// URI to enable distributed OTP sessions, token blacklisting, and rate limiting across server restarts.
2 Configure Cloudinary / S3 Image Storage
Replace placeholder credentials with active Cloudinary API credentials for real image uploads from the Admin product form.
3 Enable WATI WhatsApp Notifications
Connect active WATI endpoint to send OTP codes and order dispatch notifications to customer mobile numbers.

Execute npm run build in picky_client. Validate bundle size and ensure zero compile errors.

6. Testing & Verification Plan

Automated validation test script, user journeys, and pre-launch checklist.

Automated CLI Verification Script (scripts/verify_api.js)

A zero-dependency verification script using native Node.js fetch to assert system readiness:

  • Check 1: Health & Products: GET /api/v1/products → Assert status 200 and array length > 0.
  • Check 2: CORS Validation: Request with Origin: http://localhost:5173 → Assert Access-Control-Allow-Origin: http://localhost:5173.
  • Check 3: Admin Auth: POST /api/v1/auth/admin/login with seeded admin credentials → Assert valid JWT returned.
  • Check 4: Protected Guard: GET /api/v1/coupons with JWT → 200 OK; without JWT → 401 Unauthorized.
  • Check 5: OTP Generation: POST /api/v1/auth/send-otp → Verify Redis/In-memory key existence.
  • Check 6: Cart Pricing: Apply test coupon → Verify subtotal, discount, and grand total calculations.
